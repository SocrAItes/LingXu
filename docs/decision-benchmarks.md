# 文字决策优化实验

## 对照方法

在同一本地 Qwen3-8B 4-bit 服务上，取已有机器人录音的 6 个真实 ASR 回答节点，每个重复 3 次。直接生成、旧树选路和紧凑选路轮换运行顺序，全部要求继续追问。另构造纠正前提和切换话题两个压力场景，每个重复 3 次。

旧选路实现保存自 v0.1.2。为隔离选路改动，新旧树收到完全相同的候选池，候选由新版准备流程生成，只使用回答前的历史。此处不单独比较新旧规划器的生成质量或准备性能。

准备耗时与回答后的处理时间分别记录。回退请求独立生成，不复用直接生成侧的结果。采样温度 0.65，top_p 0.85，关闭思考输出，stream=false。经过预热，未固定采样 seed。

## 完整对照结果

以下均值与中位数按三种方案均通过程序校验的 17 组计算，各自的通过次数按全部 18 次列出。

| 方案 | 回答后平均等待 | 中位等待 | 共同候选准备，另计 | 校验通过 |
| --- | ---: | ---: | ---: | ---: |
| 直接生成下一问 | 3.489 秒 | 3.050 秒 | 无 | 18/18 |
| 旧树选路 | 4.314 秒 | 4.029 秒 | 6.287 秒 | 18/18 |
| 优化树选路 | 1.980 秒 | 1.819 秒 | 6.287 秒 | 17/18 |

本批输入的回答后平均等待较旧选路减少约 54.1%，较直接生成减少约 43.2%。这是响应等待的改善，不能据此推断总计算量或费用减少。候选准备需要额外计算，真实后台并发及其资源竞争没有在此实验中测量。

## 失败与后续修复

优化侧的一次失败来自恢复输出给出了完整问题与话题，但遗漏了 `pick`。随后增加了保守字段修复：只有候选已停用、完整新问题和话题均合法时才补 `pick=new`，原始返回与程序补齐分别保存。连续无效结构仍可回退到独立现场生成。

修复后用全部 24 组保存的真实模型响应进行离线回放，均可处理，并新增调用原失败场景 3 次，均返回有效新问题。离线回放和新增核验不混入上述完整对照的均值或通过次数，不改写原始失败记录。当前离线回归测试共 53 项。

## 正确性观察与边界

6 次纠正和切换话题测试中，新选路全部停用旧候选并现场生成问题，问句转向用户新提到的主题。这个观察只说明本批压力输入的行为，不等于真人访谈质量验收。仍可出现重复、泛泛追问、封闭式问法和对 ASR 歧义的误解。

本次只有文字模型调用，没有生成语音。数据不含 ASR、TTS、音频发送、固定转写等待或物理出声时延，不能直接与旧语音链路的平均 4.871 秒比较。样本量小，也不证明其他模型、设备或真实受访者场景的同等收益。

## 复现

准备一个机器人运行记录目录，其中包含 `frozen-inputs.json`、`tree-state.json` 和 `timing-details.json`，按部署文档配置本机文字模型后运行：

```bash
npm run benchmark:decisions -- --recording "运行记录目录" --repeats 3 --require-question
```

如需同时比较旧选路，可另准备 v0.1.2 源码目录，并通过 `--legacy-router "旧源码目录/src/model-router.mjs"` 指定旧模块。三组对照使用六种运行顺序轮换。

请求、返回、逐次结果、代码快照和协议保存在本机 `data/decision-benchmarks/`。这些记录不随仓库或发布包上传。实验会占用本机文字模型，但不会调用语音服务。
