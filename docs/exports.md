# 导出与时延

真人会话保存在本机 recordings 中；正常结束会生成同级 `会话ID-导出.zip`。语音 / 模型运行中发生错误时尽量保留已有数据；进程被强制杀死、断电或磁盘写满时不能保证完整 ZIP。

| 文件 | 内容 |
| --- | --- |
| `conversation-listen.wav` | 双方合并的试听录音 |
| `conversation.wav` | 双轨：左声道麦克风、右声道采访员播放 |
| `microphone.wav` / `interviewer.wav` | 分别保存的采集与播放音轨；macOS 另保留原始 CAF |
| `recording-clock.json` | 设备时钟起点、采样偏移与对齐依据 |
| `round-XX-识别输入.wav` | 本轮真正发给 MOSS 的语音，不是完整麦克风文件的替代品 |
| `识别原文.jsonl` / `.txt` | 原始 ASR 更新、确认、修订；含轮次和事件 ID |
| `访谈文字稿.txt` | 提问的 TTS 输入和决策当时使用的 ASR 回答 |
| `模型输入输出.txt` / `model-requests.jsonl` | 实际模型请求、返回和可观测耗时；不记录认证请求头 |
| `决策轨迹.json` | 每轮问题、ASR 来源、候选、选择与模型调用关联 |
| `tree-state.json` / `tree.json` / `tree.svg` | 树的完整状态、图结构和静态查看图 |
| `events.jsonl` | 访谈过程原始事件 |
| `latency.json` | 从事件计算的时延报告 |
| `frozen-inputs.json` | 本次规则、人物卡和模型配置快照，不含密钥 |
| `tts/` / `raw-audio/` | 合成及识别链路的原始中间音频 |

这里的“真实模型输入输出”指 API 请求和返回文本，不声称暴露模型内部隐藏推理。问题合成输入也不等于对扬声器声音重新识别的逐字结果。

## 时延解释

- 记录模型请求起止、响应头和完整响应到达、候选预生成与选路、TTS 请求与首个音频块、音频入队、播放完成等可观测事件。
- 文字调用目前 `stream=false`，没有首 token 实测，报告将该值记为不可用。
- 不将传输耗时推算成未暴露的 STT / LLM / TTS 内部运算耗时；未取得服务端时间戳的部分保留为不可测。
- macOS 播放完成回调来自系统播放器；Windows 使用 PortAudio 估计的输出 DAC 时间。它们都不是外部麦克风测得的声学扬声器时延。
- `conversation.wav` 的输入 / 输出来自设备轨道并按原生时钟对齐；与机器人模式的纯数字中继录音含义不同。

记录包含自己的语音、文本、路径与服务器模型地址等信息。分享某次导出时，应按实际分享范围自行检查内容；公开发布包不会携带这些会话记录。
